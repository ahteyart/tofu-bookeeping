# Bukku connector (draft)

Bukku (bukku.my) is a Malaysian cloud accounting system. It becomes the first `provider` of Module 2
(Ledger Connector), replacing Xero as the default target.

> Unverified: Bukku's official API reference was not reachable. Third-party integrations (e.g. HitPay)
> indicate auth is a **company subdomain + API access token** generated in Bukku under
> Settings -> API integrations. All endpoint paths and field names below are **TBD** until checked
> against Bukku's developer docs or confirmed with Bukku support.

## Connection

| Field | Source |
|-------|--------|
| `subdomain` | Client's Bukku company subdomain |
| `access_token` | Generated by the client in Bukku; stored encrypted, never logged |

Stored in `ledger_connection` (`provider = 'bukku'`).

## Adapter interface (provider-agnostic)

```ts
interface LedgerAdapter {
  testConnection(): Promise<void>;
  // Pull (Bukku -> us)
  listAccounts(): Promise<Account[]>;        // chart of accounts
  listTaxCodes(): Promise<TaxRate[]>;        // e.g. SST codes
  listContacts(): Promise<Contact[]>;        // suppliers / customers
  listCurrencies(): Promise<string[]>;
  // Push (us -> Bukku)
  createPurchaseBill(b: BillDraft, key: string): Promise<{ externalId: string }>;
  createExpense(e: ExpenseDraft, key: string): Promise<{ externalId: string }>;
  attachFile(externalId: string, file: Buffer, name: string): Promise<void>;
}
```

`key` is our idempotency key (`posting.idempotency_key`); Bukku may not support idempotency natively,
so check for an existing document by supplier + number + date before creating.

| bank statement line | Bank transaction / reconciliation |

## Malaysia-specific notes

- Default `base_currency` MYR, multi-currency per document.
- SST tax codes per client; keep tax mapping in `coding_rule`.
- e-Invoice (LHDN MyInvois) is handled by Bukku on the sales side; this system covers purchases.

## Sync

- Initial full pull on connect, then scheduled incremental refresh (accounts, tax codes, contacts).
- Posting retries with backoff; failures recorded in `posting.error` and surfaced in the review queue.
